# ORACLE_SEAM_AUDIT

작성일: 2026-11-18  
목적: E2 결과표가 Oracle의 점수·변수·순위를 직접 노출하는지, 기업의 기초 재무정보와 결합될 때 평가정보를 간접 전달할 수 있는지 기록한다.

## 결론

결과표에는 α·β·γ 점수, 신용등급, 평가모형 가중치 또는 행동 순위가 직접 포함되지 않는다. 그러나 Simulator 결과표의 항목은 평가모형이 사용하는 재무 입력 또는 그 비율의 구성요소일 가능성이 높다. LLM이 보는 기초 기업 재무정보와 변화량을 결합하면 평가에 사용되는 비율을 직접 계산할 수 있다.

따라서 통제할 수 있는 주장은 “점수·등급·가중치를 프롬프트에 직접 제공하지 않는다”이다. “평가정보를 보지 않는다”, “평가신호가 전혀 전달되지 않는다”는 주장은 이 자료만으로 할 수 없다.

## 예정 결과표 열과 평가정보 연결 가능성

| Simulator 결과표 열 | 평가변수에 대한 잠재적 연결 | 현재 확인 정도 | 정보 전달 해석 |
|---|---|---|---|
| 매출액 변화 | 매출 대비 영업이익·순이익·운전자본 비율, 자산회전율의 분모 | 공식 Oracle 산식과 대조 전 | 기초 매출 및 결과표를 함께 보면 수익성·운전자본 비율 변화를 추산할 수 있음 |
| 영업이익 변화 | 영업이익률의 분자, ROA·이자보상 지표의 근사 분자 | 공식 Oracle 산식과 대조 전 | 수익성 및 부채상환 능력에 대한 정보가 될 수 있음 |
| 세전이익 변화 | 세전 수익성·이자비용 차감 전후의 수익력 지표 | 공식 Oracle 산식과 대조 전 | 평가용 지표를 직접 쓰지 않아도 기업의 이익 상태 변화를 제공 |
| 이자비용 변화 | 이자보상배율, 이자부담, 부채서비스 능력의 입력/분모 | 공식 Oracle 산식과 대조 전 | 기초 이익과 결합하면 이자보상 변화를 산출할 수 있음 |
| 총차입금 변화 | 부채비율·차입금의존도·차입금/EBITDA·OCF/부채의 부채 입력 | 변수 목록과 개념적 관계는 확인, α·β·γ 원 산식 미확인 | 레버리지 지표를 직접 또는 간접 계산할 수 있음 |
| 단기차입금 변화 | 단기부채 비중, 현금/단기차입금, 단기 유동성 비율 | 변수 목록과 개념적 관계는 확인, 원 산식 미확인 | 만기구조·단기상환 부담 정보 제공 |
| 현금및현금성자산 변화 | 현금비율, 현금/단기차입금 및 현금흐름 커버리지 | 원 산식 미확인 | 유동성과 상환여력 비율의 직접 구성요소가 될 수 있음 |
| 유동자산 변화 | 유동비율·순운전자본의 자산 항목 | 원 산식 미확인 | 기초 유동부채와 결합해 유동비율을 계산할 수 있음 |
| 유동부채 변화 | 유동비율·현금비율·운전자본 지표의 분모 또는 부채 항목 | 원 산식 미확인 | 위 항목들과 함께 유동성 비율 추산에 쓰일 수 있음 |
| 자본총계 변화 | 부채비율·자기자본비율·부채/자본 지표 | 원 산식 미확인 | 레버리지와 지급능력 정보 제공 |
| 영업활동현금흐름 변화 | OCF/총부채·현금흐름 커버리지 | δ·ε 관련 변수 명세와 개념상 연결, 실제 α·β·γ 식 미확인 | 현금흐름 기반 신용위험 평가정보를 직접 구성할 수 있음 |

위 표에서 “잠재적 연결”은 금융비율의 일반적인 산술 관계와 이번에 해시를 확인한 GitHub Oracle 계약/입력 자료에 근거한다. α 계약의 선택변수 이름과 파라미터 파일은 확인했지만, 모든 예정 표 열에서 α·β·γ의 변환·산식으로 이어지는 완전한 crosswalk는 수행하지 않았다. 특정 변화량 열이 특정 점수 항의 직접 입력이라고 확대해 단정하지 않는다.

## 확인된 평가모형 변수 목록의 범위

v3 설계서에는 δ와 ε의 입력 비율 목록이 기록되어 있다. 이번 복구에서는 11/17 ZIP의 `delta_train.py`, `fam2.py`와 연결 자료를 사용해 두 challenger 모형을 재적합·검증했고, 재현 결과는 `E2_SOURCE_AUDIT.md`와 `E2_REPRODUCTION_REPORT.md`에 기록했다. 따라서 이들 변수 목록은 코드와 데이터의 실제 실행을 통해 확인됐다. 다만 δ·ε은 관측된 등급변동 라벨로 적합된 challenger score이지 실제 향후 기업성과를 검증하는 모형이 아니다.

α Oracle 파라미터 파일과 동결 계약, α 입력 선택변수(`R006`, `R064`, `R085`, `R116`, `R157`, `R182`, `cap_change_count_3y`, `log_assets`, `operating_loss_freq_3y`)를 확인했다. β·γ 및 예정 표의 각 열에 대한 전체 변환·산식 crosswalk는 아직 완성되지 않았다. 표의 변화를 실제 점수 항과 연결해 직접 누출 여부를 단정하지 않는다.

## 간접 누출 위험과 해석

1. LLM 프롬프트는 기업의 기초 재무상태를 포함한다. 여기에 결과표의 재무 항목별 변화를 더하면 pro forma 값을 계산할 수 있다.
2. 기초 및 변화량은 Oracle에 사용된 비율의 분자·분모와 겹칠 수 있다. 이는 Oracle 점수 자체를 주는 것과 같지는 않지만, 평가모형과 정렬되는 재무 계산을 가능하게 한다.
3. E2-T와 E2-RT에 동일한 표를 쓰면 표 자체의 노출량은 조건 간 통제되지만, E2-N/E2-R 조건과 비교할 때 정보가 추가되는 것은 실험 처치의 일부다. 결과표 효과에는 재무 시뮬레이션 피드백과 Oracle 입력 proxy가 함께 들어갈 수 있다.
4. 그러므로 E2-T/RT 결과는 “평가점수를 보지 않고 Simulator의 재무 정보를 제공한 효과”로 해석한다. “평가정보와 독립적인 결과 신호” 또는 “실제 재무 결과를 보고 수정”이라는 표현은 피한다.
5. 정확한 직접/간접 seam 분석은 본 실행 전에 α·β·γ의 전체 feature schema, 시뮬레이터 input/output schema, 기초 재무정보를 함께 대조해야 한다. 현 상태는 변수 일부와 간접 추론 가능성을 확인한 부분 감사다.

## B0에서 요청할 최소 감사자료

- Oracle α·β·γ의 전체 원변수 이름, 계산식, 방향, 정규화, 계수/가중치 및 버전 hash를 표의 각 출력 계정과 crosswalk
- E2 결과표의 행별 금액·부호·단위·시점, Simulator 기업 입력 feature schema 및 재무계정 연결표
- 각 변화량에서 pro forma financial statement를 계산하는 절차 및 회계 검증
- LLM에 제공되는 기초 재무정보의 전체 필드 목록
- 모델에 결과표를 주기 전후의 변수·점수·순위 금지 문자열 검사 규칙

이 자료가 확보되기 전에는 직접적인 점수 누출은 없다고 쓸 수 있지만, 간접 평가정보 전달은 남아 있는 제한으로 보고한다.
