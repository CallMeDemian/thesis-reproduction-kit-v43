# E2 최종 실험설계서 v5.1 — 정책 참조와 재무결과 정보의 결합
2026-11-18 | Codex / Claude Code 실행 지시서

**v5.1 변경:** T/RT 전용 추가 행동 지시 삭제, 두 재무 가정 민감도 필수화, 결과표–Oracle 입력변수 crosswalk 필수화. 나머지 실험 조건·요청 수·주 가설은 v5와 동일하다. v5는 보존한다.

## 0. 작업 목표와 범위

기존 연구의 RL 참조 기반 LLM 재무권고를 추론 시점에서 개선한다. 학습된 기업별 행동(정책 참조)과 회계 Simulator가 계산한 행동별 재무결과(결과표)를 동시에 제공하면 기존 RL 참조만 제공할 때보다 권고 품질이 높아지는지 검증한다.

- 본 실험의 평가기는 기존 동결 Oracle-α·β·γ만 사용한다. δ·ε 학습·채점·논문 편입은 하지 않는다. 과거 도전자 분석은 보존만 한다.
- 행동 선택, 결과표 생성, 참조 결정 및 LLM 권고 수정에 Oracle 점수·가중치·순위·평가기 기반 선택을 사용하지 않는다. 기존 C3-E 구성의 최종 선택에 2024 α가 사용된 이력은 명시한다. Simulator의 재무정보는 평가변수와 겹칠 수 있다.
- RL 재학습, 행동 계약 변경, 신규 기업자료 수집, 기존 Frozen 원본 수정, 원격 push는 범위 밖이다.
- 기존 연구의 결과는 E2 결과와 분리한다. E2 실패 시 기존 연구를 소급 변경하지 않는다. 기존 575개 기업의 추가 실험이며 새로운 독립 표본외 검증이나 실제 기업성과의 입증이 아니다.
- 핵심 2×2 실험에 필요하지 않은 C2/BC 조건(E2-B)은 제외한다. C2 계보 탐색을 이유로 실행을 지연시키지 않는다.

## 1. 연구의 차별점과 검증할 문제

| 기존 접근 | 한계 또는 연구 질문 | E2의 기술적 접근 |
|---|---|---|
| 자기 재검토 | 같은 입력을 재검토하는 것만으로 충분한 개선이 나타나는가? | 별도 학습·계산된 기업별 정보 제공 |
| 학습된 정책 참조(C6-E) | 9개 표준행동에서 선택된 참조 이후에도 자유 8축의 조합·강도 개선 여지가 있는가? | 정책 참조와 행동별 재무변화를 함께 제공 |
| 결과 예측·시뮬레이션 활용 | 재무결과 정보만으로 충분한가? | 동일 초안의 2×2 실험으로 두 정보의 증분과 상호작용 분리 |

조언자와 시뮬레이션은 이미 연구된 기술이다. 기존 관련연구의 모든 방법이 한 정보원만 사용한다거나 평가모형을 반드시 최적화에 사용한다고 주장하지 않는다. 본 연구의 차별화는 기업 재무행동 학습정책과 회계적 행동 결과의 결합, 자유 8축 권고, 기존 검증 평가환경에서의 통제된 비교에 있다. 세계 최초의 결합이라는 주장을 하지 않는다.

이번 B1 사용자 전달 보고상 P3의 α 증분은 RL 대비 +0.078 [0.049, 0.111], 절대 정책가치는 약 1.001이다. P3는 RL이 OE를 선택한 기업만 COGS 단일축 행동으로 대체한다. 이 값은 실제 B1 CSV 원본에서 확인하고 동결한다. P3는 동결 결과를 본 뒤 발전시킨 탐색적 기준선이다. E2의 프롬프트에는 주입하지 않는다.

R8(기존 분석): α에서 C3-E 전체/구성/배정 0.923/0.584/0.339, GPT C6-E 0.912/0.615/0.297, Gemini C6-E 0.885/0.621/0.264. 이 분해는 결과의 성분이지 기능 분담이나 원인의 입증이 아니다. R9의 비용축 반반 배분(참조 없는 비용 권고 1,545/1,893)은 동기이지 그 자체로 오류는 아니다. B1의 배분변경 계산은 Simulator 내부 반사실이며 실현성과의 인과효과가 아니다.

## 3. 실험 조건과 요청 수

동일 기업·모델·실행의 C4 초안, 원 기업정보, 원 행동계약과 출력 스키마를 공통으로 사용한다. 수정 요청은 각각 독립적으로 생성하며 한 조건의 응답을 다른 조건으로 넘기지 않는다.

| 조건 | 기업별 RL 행동 | 공통 10행 결과표 | 역할 |
|---|---|---|---|
| E2-N | 없음 | 없음 | 자기 재검토 기준선 |
| E2-R | C3-E | 없음 | 기존 RL 참조 방식 |
| E2-T | 없음 | 있음 | 결과 정보만의 효과 |
| E2-RT | E2-R과 동일 | E2-T와 동일 | 제안 방법 |
| E2-Q | 없음 | 없음 | 별도 재무결과 예측 과제(권고 수정 아님) |

- N/R은 기존 C4R/C6-E와 같은 의미·출력규칙을 유지한다. R/RT의 참조 JSON과 참조 문구는 동일하고 출처는 숨긴다. T/RT의 표는 바이트까지 동일하다. 조건표에 없는 조언을 추가하지 않는다.
- 본실험: 575×2 모델×2 실행×4 수정 조건=9,200건. Q는 1차 초안을 사용하여 575×2 모델=1,150건. 총 10,350 논리 요청. 별도 100개 기업 품질 파일럿은 1회×2 모델×5 조건=1,000건. 기본 계획 합계 11,350건(재시도 제외).
- Q는 보조 진단으로 핵심 2×2 실행과 독립적이다. Q 파싱 문제로 N/R/T/RT를 중단하지 않는다.
- 호출은 기존 provider 배치 경로를 선호한다. 요청 행렬, 토큰/비용 추정, 실제 모델 ID, 재시도 정책을 파일럿 전 보고한다. 조건별 같은 모델·추론 설정·출력 토큰 상한을 이용하고, 길이 차이는 정보 처치의 일부로 기록한다. 무작위 호출 순서(고정 seed 20261118), 독립 요청, run id로 시점 드리프트를 줄인다. 재시도는 기존 계약에 따르고 실제 호출 수와 비용을 별도로 기록한다.

## 4. 결과표와 프롬프트

기존 B1 `e2_simulator_10row_prompt_view.parquet`를 우선 재사용한다. 기업별 10행은 A0, 해당 모델·반복의 C4 초안, 8개 단일축 1 normalized unit이다. referent RL 행동 결과 행이나 P3 등 신규 후보 행을 추가하지 않는다. 각 행은 동일 무행동 기준에서 따로 실행한 결과다.

열: 매출액, 영업이익, 세전이익, 이자비용, 총차입금, 단기차입금, 현금및현금성자산, 유동자산, 유동부채, 자본총계, 영업활동현금흐름의 무행동 대비 금액 변화. 천원(KRW thousand)을 원칙으로 원 계약에서 확인하고 단위·시점·반올림을 명시한다. 실행불가와 효과 0을 구분한다. 각 행에는 행동 종류와 해당 실제 축별 크기를 명시하고, 순위나 가치판단을 적지 않는다. 표에 점수, 등급, Oracle 가중치, 행동 순위, P3의 성과를 포함하지 않는다.

행동 계약: 기존 8축의 부호·척도·한도·동시제약을 유지한다. B1 정규화 총행동크기 T≤1. COGS 1단위 원 척도 0.0268826066, SGA 0.0171694674가 원 계약과 일치하는지 확인한다. 이 두 행동의 단위가 다르므로 같은 예산은 같은 비용률 개선폭을 뜻하지 않는다. E2는 원 계약 하에서의 개선만 주장한다.

### 프롬프트 추가 문구(T/RT 공통)

“아래 표는 회계 Simulator가 계산한 각 행동의 1년 뒤 재무제표 금액 변화(무행동 대비)입니다. 여러 행동을 함께 적용할 때 효과는 단순히 더해지지 않을 수 있습니다.”

최종 권고 지시·행동 계약·출력 규칙은 네 조건 모두에서 원래 C4R/C6-E의 공통 문구를 그대로 사용한다. RL 참조 정보 블록만 R/RT에, 결과표와 위 두 설명 문장만 T/RT에 추가한다. 기존 원문에서 조건별로 다른 지시가 발견되면 비처치 문구를 공통화하고 차이를 기록한다. 네 조건의 프롬프트 diff를 저장하여 행동 종류·조합·강도 결정, 목적함수, 추론 강도에 관한 추가 지시가 T/RT 전용으로 들어가지 않았음을 확인한다. 표가 붙는다는 이유로 행동 목표나 추론 지시를 별도로 강화하지 않는다. 특정 축 집중, 비용률 반반 금지, P3 행동, 정책가치 극대화 수식을 알려주지 않는다. 표의 길이에 따른 효과를 별도 통제하지 않으므로 결론은 '이 결과표를 추가한 정보 패키지의 효과'이며 순수 내용 대 토큰 수 효과를 구분하지는 못한다.

### Oracle 입력변수 연결표(필수, 분석자용)

11개 결과표 열과 기존 α·β·γ의 실제 입력변수 사이의 관계를 공식 feature schema, 산식, 변환 및 Simulator 출력 코드에서 확인하여 `ORACLE_SEAM_CROSSWALK.md`로 남긴다. α의 9개 선택변수는 기존 계약에서 확인한 R006, R064, R085, R116, R157, R182, cap_change_count_3y, log_assets, operating_loss_freq_3y이며, β·γ의 실제 입력·변환도 각각 대조한다. 11개 열을 행으로 두고 평가변수명·산식·직접 입력/비율의 분자·분모/간접 추론/연결 없음·기초정보 추가 필요 여부·코드 근거와 미확인 사항을 기록한다. 이름이 비슷하다는 이유로 관계를 추측하지 않는다. Oracle 점수·가중치·신용등급 예측·행동 순위의 직접 노출은 금지하지만, 공통 재무정보와 평가변수의 중첩 자체는 처치의 일부다. 연결표와 Oracle 상세 산식은 분석자용이며 LLM 프롬프트로 전달하지 않는다. 이 점검으로 평가정보의 완전한 독립을 주장하지 않는다.

## 5. E2-Q (보조 예측 진단)

1차 C4 초안과 8개 단일축 행동 각각에 대해 동일한 원 기업정보만으로 세전이익·이자비용·총차입금·현금·유동부채의 무행동 대비 변화 방향 및 예상 변화액(천원)을 답하게 한다. Simulator 답이나 RL 참조를 주지 않는다. 9행×5항목을 고정 JSON으로 받는다.

v4의 변화율 대신 변화액을 직접 예측하게 한다. 음수·0에 가까운 기초값 문제를 피하고 재무 규모를 통제하기 위해, 양의 기초 총자산으로 실제 및 예측 변화액을 나누어 평가한다. 기본 무변화 범위는 절대 변화가 기초 총자산의 0.01% 이하(1bp)로 양쪽 동일하게 둔다. 이는 E2 신규 설계상의 임계값이며 경제적 유의성의 보편 기준이 아니다. 0/1/10bp 민감도를 함께 보고한다. 기초 총자산이 비양수/결측이면 해당 항목을 채점불가로 분리한다.

방향 정확도(증가/감소/유의미한 변화 없음), 무변화 오탐률, 정규화 절대오차 중앙값, 실제 변화가 1bp를 초과하고 방향이 맞는 항목 중 예측 크기가 실제의 0.5~2배 범위 밖인 비율을 보고한다. 분모와 파싱 실패 수를 공개한다. 실행불가 행은 별도 보고한다. Q는 Simulator와의 일치도를 측정하는 것이며 실제 정확한 미래예측력 또는 결과표 개선의 인과 메커니즘 자체를 입증하지 않는다.

## 6. 평가와 비교 기준

S_k(i,a) = Oracle-k(Simulator(i,a)) − Oracle-k(Simulator(i,A0)), k∈{α,β,γ}. 각 조건은 원 연구의 STRICT ITT(파싱/계약 위반 등은 원 규칙에 따라 A0)로 우선 평가한다. 인프라 실패와 모델의 무효 권고는 분리하고, 원 계약을 확인해 실패 처리를 고정한다. 점수 단위는 원 Oracle 단위이며 0~1 확률이라고 부르지 않는다.

비교 대상은 P0=C3-E, P1=OE 고정, P2=COGS 단일축 고정, P3=RL의 OE만 COGS로 대체, 기존 P4/P5(선택 기준을 확인한 경우)를 고정한다. P3는 강한 탐색 기준선이지 E2 주 가설의 성공 조건은 아니다. P4/P5는 탐색적 보조 비교로 모두 보고하고 결과를 본 뒤 좋은 것만 골라 제시하지 않는다. 기존 C4/C4R/C6-E 값은 과거 결과로 참고하며 E2의 주 비교는 같은 시기 R이다.

| ID | 대비/분석 | 역할 |
|---|---|---|
| H1 | RT−R | **유일한 주 가설: α 정책가치에서 기존 방법 개선** |
| H2 | T−N, R−N, RT−T | 두 정보원의 개별 효과와 RT에서 RL의 추가 가치 |
| H3 | RT−R−T+N | 상호작용(두 정보원의 효과가 단순 합을 넘는지) |
| H4 | RT−P0, RT−P1, RT−P2, RT−P3, RT−P4/P5 | RL 단독 및 단순/재무 규칙 대비 LLM 가치 |
| H5 | RT−R의 구성·배정 성분과 실제 축별 배분 변화 | 개선분 설명 |
| H6 | Q 예측 오류 | 문제 진단 |

통계: 기업별 두 모델×두 실행 차이를 평균한 후 표본 평균 및 기업 단위 paired percentile bootstrap 95% CI(10,000회, PCG64 seed 20261118, 모든 조건의 같은 기업 묶음 및 공통 재표집 인덱스)로 H1을 판단한다. 하한>0이면 α 기준 주 가설 지지. 모델별 두 실행 평균, 실행별 값, β·γ의 동일 대비와 CI, 유효율 및 무행동 비율도 보고한다. 모델별 H1 p값은 centered paired bootstrap 검정 또는 기존 논문의 검정 계약을 사전 지정하고 Holm 보정한다. H2~H6은 보조·탐색이며 유의성을 주장하는 복수 대비의 family와 검정 방법을 실행 전 기록한다. 비유의는 동등성이 아니다. α가 개선돼도 β·γ가 악화하면 trade-off를 명시한다. 요구된 본실험은 같은 575개 기업의 조건부 효과이지 두 모델을 넘어선 일반화가 아니다.

## 7. 구성·배정 및 P3와의 개선 여지 비교

정책 π의 실제 행동 a_i에 대해 V=mean_i S(i,a_i), C=mean_{i≠j} S(i,a_j), A=V−C. 자신을 제외한 기업 간 재배정이라는 정의를 명시하고, 기존 R8의 20회 섞기와 수치가 정확히 같아야 한다고 강제하지 않는다. 매 모델·반복에 별도로 계산한 뒤 평균한다. 유효하지 않은 교차행동은 원 평가 규칙대로 처리하고 비율을 기록한다. 실행 가능성 층 내 재배정은 보조로 보고한다.

가능하면 모든 ordered pair를 점수화한다. 계산량이 크면 결과 열람 전 100개 공통 derangement(자기 배정 없는 순열)를 seed 20261118로 고정한다. 공통 순열 민감도와 고정 행동 A≈0를 확인한다. 기업 bootstrap은 원 기업별 score surface에서 재표집 집합의 C를 다시 계산한다(원 기업 인덱스가 같은 쌍을 제외하고 분모 재계산). 전체 surface 없이 순열로 근사한 경우 C/A CI의 근사법을 별도 명시하고 정확한 재배정 bootstrap이라고 하지 않는다. 이 분석이 전체 본실험을 지연시키지 않게 한다.

P3와의 비교는 두 가지를 구분한다.

- 전체 기업: D=V(P3)−V(R), G=V(RT)−V(R). D>0인 경우 G/D를 '동시기 RL 참조에서 P3까지의 점수 격차 회수율'로 보고한다. 100%는 P3와 동일 점수, 그 이상은 P3 초과, 음수는 악화다. 분모가 0 근처이거나 음수이면 회수율을 생략하고 G, D, RT−P3만 제시한다. 이는 P3의 개선분을 LLM이 동일한 행동 메커니즘으로 찾았다는 뜻이 아니다.
- RL이 OE를 선택한 고정 사전 하위집단: R과 RT의 COGS/SGA 정규화 비중, 비용축 총배분, 다른 축 배분, 참조와 거리, P3 행동의 채택률, RT−R 및 RT−P3를 보고한다. 나머지 기업도 별도로 보고하여 기존 RL 행동이 불필요하게 훼손되는지 확인한다. 사전 고정 하위집단이며 결과에 따라 기업을 고르지 않는다. P3와 동일한 행동이 아니더라도 높은 평가점수를 낼 수 있다.
- 비교 가능한 비용축 분석: COGS/SGA 모두 0인 경우 비율은 NA. 비용축 총배분 및 비율을 분리한다. 전체 ITT, 양 조건 비용축 사용 기업의 paired 분석을 구분한다(후자는 사후 선택 조건부 설명). 기존 반반 배분 기준과 tolerance를 재사용한다.

## 8. 실행 순서와 중단 규칙

A. 준비: 2절 최소 확인, 결과표/프롬프트 조립, P3 등 기준선 확인, E2 요청 및 분석 protocol 동결. 원본 v4와 protocol은 보존. 새로운 v5.1 request/analysis protocol과 SHA-256을 저장한다. 두 필수 민감도 경로의 구현 및 회계/행동 계약 점검 계획과 Oracle 입력변수 crosswalk를 파일럿 전에 확인한다. 반복적인 기존 자료 감사나 R1~R9 재현은 하지 않는다.

B. 100개 기업 품질 파일럿: C3-E 행동 종류에 비례한 고정 층화 추출(seed 20261118), 두 모델·1차 실행·4 수정 조건과 Q, 총 1,000개 논리 요청. 조건 간 표/부모/참조 동일, 출력 파싱·행동 계약·완료율, 47개 처리 규칙, 표의 의미와 실제 응답 사례를 검사한다. 각 조건·모델의 strict usable 비율이 95% 미만이거나 구조 오염/시스템 오류가 있으면 원인만 분석한다(95%는 운영상 경보 기준이지 연구가설 기준 아님). **Oracle 성능점수는 파일럿에서 계산/열람하지 않는다.** Q도 정답 채점 대신 출력 구조와 정답 생성 가능성만 확인한다. 프롬프트 변경이 필요하면 이유·차이를 기록하고 수정된 안으로 품질을 다시 확인한다. API 비용과 호출 수를 보고한다.

C. Gate: 품질 파일럿 보고 후 본실험 승인을 받는다. 성능을 확인하기 위한 탐색 파일럿으로 바꾸고 싶다면 점수 열람 전에 별도 사용자 결정이 필요하다. 그 경우 100개 기업 결과와 나머지 475개 기업의 신규 응답 평가를 분리하고, 기존 575개에 대한 사후 지식과 선택 효과의 한계를 명시한다. 파일럿 점수를 보고 방법을 바꾼 뒤 전체 575개를 사전지정 독립 확증 분석이라고 부르지 않는다.

D. 본실험: 파일럿을 본실험에 재사용하지 않고 전체 575개에 대해 10,350건 독립 요청을 실행한다. 특정 모델/조건/기업만 성능을 보며 재시도하거나 조기 중단하지 않는다. 전체 생성 완료 후 기존 α·β·γ 채점기를 연결하고 고정 분석을 실행한다. 추가 LLM 호출 금지. 실패·부정 결과도 제시한다.

D-1. **필수 재무 가정 민감도(T9)**: 기존 Simulator 기준 설정 S0에 더하여 아래 두 조건을 각각 독립 적용한다. 11/17 `구조적재검토_분석스크립트_20261117.zip`의 교란 코드를 우선 사용하고 정확한 경로·해시·산식·적용 범위를 기록한다. 구현이 없거나 호환되지 않으면 구현 방식을 먼저 보고하고 확정한다. 가정을 누락하거나 유리한 결과만 선택하지 않는다.

| 시나리오 | 변경 가정 | 검증 목적 |
|---|---|---|
| S0 | 기존 동결 Simulator | 사전 지정 주 분석 |
| S1 | 장기 전환분 가산금리 +1%p | 리파이낸싱의 이자비용 및 유동성 효과에 대한 의존성 |
| S2 | 비용절감 실현율 50% | COGS/SGA 비용절감 효과의 실현 가정에 대한 의존성 |

- S1은 전환된 채무에 추가 금리를 부과하는 설정이다. 기존 교란 구현의 정확한 대상 원금·기간·기준금리 처리와 회계 반영 방식을 확인하며 전사 차입금에 임의로 1%p를 가산하지 않는다. S2는 해당 행동으로 발생하는 증분 비용절감액의 실현을 제한한다. 기존 구현에서 실제 적용되는 COGS/SGA 범위·복합행동·회계 반영을 확인하며 전체 영업비용을 임의로 절반으로 줄이지 않는다.
- S0에서 생성·처리한 N/R/T/RT의 행동 벡터 및 사전 고정 P0~P5 행동 벡터를 그대로 유지한다. P5도 교란된 점수를 기준으로 다시 고르지 않는다. 스트레스 결과를 다시 프롬프트로 제공하지 않고 참조·행동·표·모형·표본·Oracle 가중치도 변경하지 않는다. 각 시나리오에서 같은 가정의 A0를 별도 계산하고 S_k(i,a)=Oracle-k(Simulator_s(i,a))−Oracle-k(Simulator_s(i,A0))로 α·β·γ 모두 재채점한다. 실행불가 및 회계 처리 규칙은 원 계약에 따라 사전 고정하고 시나리오별 예외 수를 공개한다.
- 시나리오별로 모든 조건/P0~P5의 평균 정책가치와 주요 대비 RT−R, RT−P0, RT−P2, RT−P3를 같은 기업 묶음·동일 부트스트랩 인덱스로 계산한다. 모델별 및 통합 차이·95% CI, 기준 S0 대비 변화량(각 대비의 S1/S2 값−S0 값과 paired CI)을 보고한다. 두 시나리오의 조합은 필수 범위가 아니며 사후에 유리한 시나리오만 고르지 않는다.
- 주 가설은 S0의 α RT−R로 유지한다. S1/S2는 필수 보조 강건성 분석이다. 두 조건에서도 개선 방향과 CI가 유지될 때 그 가정 변화 하의 강건성을 주장한다. 점추정치는 양수지만 CI가 0을 포함하면 방향 유지와 통계적 불확실성을 구분한다. 개선폭 감소 또는 부호 역전은 가정 의존성을 보여 주며, 이것만으로 Simulator 허점 악용이나 실제 기업성과의 실패를 입증하지 않는다. 스트레스는 고정 권고의 사후 민감도이며 교란된 Simulator 정보로 LLM을 다시 생성하는 적응력 실험이 아니다.

기존 v4와 B1 완료 산출물을 재사용하여 v5.1로 전환한다. v5.1의 공통 지시문 통제, Oracle crosswalk 및 필수 스트레스 경로 준비를 반영한다. δ·ε·E2-B·R1~R9 추가 재현 작업은 제외한다. 원 출력을 보존하고 47개 초안 처리와 요청 연결을 마친 후 100개 기업의 **품질 파일럿**까지만 진행한다. 요청 수, 비용, 유효율, 표·참조 통제 및 사례를 보고하고 본실험은 사용자 승인 후 실행한다. 불필요한 감사 반복이나 무단 방법 변경 없이 핵심 2×2 실험을 완성하는 것이 목표다.
