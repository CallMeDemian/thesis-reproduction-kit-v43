# E2 v5.1 본실험 재사용·실행 프로토콜

상태: **점수 열람 전 고정**  
고정 시점: 2026-11-19 (Asia/Seoul)  
상위 설계: `E2_V5_1_PROTOCOL.md`와 원본 `source_inputs/E2_최종_실험설계서_v5.1_20261118.md`는 보존한다. 이 문서는 사용자가 승인한 기존 자료 재사용과 파일럿 편입을 위한 실행 보충서다.

## 1. 분석 전 점수 차단

재사용 연결·요청 조립·신규 생성이 끝날 때까지 기존 또는 신규 α·β·γ 성능점수를 조회하거나 계산하지 않는다. 이 문서를 쓰는 동안 확인한 것은 요청 메타데이터, 프롬프트, 응답 원문/해시, 실행 설정, API 사용량, 구조·행동 계약 및 Simulator 결과표 계약뿐이다. 과거 성능 요약·점수 파일은 열지 않는다.

전체 신규 생성이 완료되고 원응답 무결성 검사를 마친 후에만 v5.1의 고정 파서·행동 계약으로 정책을 평가한다. 분석 점수를 보고 생성·프롬프트·표본·행동·가설·통계 기준을 바꾸지 않는다. E2 평가에는 α·β·γ만 사용하며 E2-B, δ·ε, RL 재학습은 제외한다. 다만 최신 사용자 지시에 따라 과거 R6 계산 복원은 E2 평가와 분리해 수행한다. R6에 기존 평가 자산이 필요하면 복원 목적으로만 사용하고, R6 작업이 신규 E2 생성·분석을 지연시키지 않게 한다. 추가 LLM 생성은 요청된 5,150건과 사전 고정한 인프라 실패 재전송에 한정한다.

## 2. 조건, 수량 및 재사용 규칙

표본은 동일한 575개 기업, GPT-5.4-mini와 Gemini 3.1 Flash-Lite, 권고 조건별 2회, Q 1회다. N/R/T/RT의 STRICT ITT는 기존 E1 파서·행동 계약을 따른다. 무효 권고는 8축 A0로 고정하고, 공급자 전달 실패·응답 부재는 모델 무효와 분리한다.

| 조건 | 최종 행 수 | 재사용 원천 | 재사용 | 신규 논리 요청 |
|---|---:|---|---:|---:|
| N | 2,300 | 기존 본실험 C4R, 575×2모델×2회 | 2,300 | 0 |
| R | 2,300 | 기존 본실험 C6-E, 575×2모델×2회 | 2,300 | 0 |
| T | 2,300 | 100기업 파일럿 첫 회차 + 신규 첫/둘째 회차 | 200 | 2,100 |
| RT | 2,300 | 100기업 파일럿 첫 회차 + 신규 첫/둘째 회차 | 200 | 2,100 |
| Q | 1,150 | 100기업 파일럿 + 신규 475기업 | 200 | 950 |
| **합계** | **10,350** |  | **5,200** | **5,150** |

신규 요청은 각 공급자별 T 1,050건, RT 1,050건, Q 475건이다(공급자당 2,575건). 파일럿 T/RT의 100기업 응답은 첫 회차에만 편입하며, 둘째 회차는 575기업 전부 신규 생성한다. 파일럿 Q는 100기업 응답을 편입하고 나머지 475기업만 새로 생성한다. 파일럿 N/R은 전체 본실험 결과에 합치지 않고, 100기업·첫 회차의 동시기 2×2 보조 분석에만 쓴다.

각 요청은 `row_id × firm_key × model_key × replicate × condition`으로 고유하게 연결한다. 기존 C4R/C6-E는 동결 원장의 선택된 시도 인덱스, 전달 잠금 상태, 원문 및 선택 원문 해시가 모두 있는 레코드만 재사용한다. 파일럿은 제출 요청 ID와 응답 ID, 프롬프트 해시, 원문 응답을 매니페스트와 대조한다. 성능점수에 따라 누락된 모델 출력을 보충하지 않는다. 공급자 인프라 오류로 논리 요청 자체가 전달되지 않은 경우에만 오류·재시도 레코드를 보존한 채 1회 재전송을 허용하며, 모델 출력의 파싱 실패·무효 행동·낮은 점수는 재생성 사유가 아니다.

## 3. 권위 원천과 재사용 검증 기준

기존 본실험 응답 원천은 작업공간의 `archive/DEPLOYED_RELEASE/llm_runs/final_plan3/d5d878bf50718bac65ede73df3fc88c16723870b6c90a790557ff35b063b7ba7/`다. 그 `release.json`은 기준 릴리스 해시 `2cf6d6d0e4250e66ce882ab95f9d641f2c73711ffbc6429e9a203dcc2ee680a2`에 기반하고, 575개 기업·2모델의 24,150 요청, HIGH 추론, `gpt-5.4-mini-2026-03-17` 및 `gemini-3.1-flash-lite`, 32,768 출력 상한을 기록한다. GitHub 동결 원천의 `logical_requests.parquet`와 동일 기준 릴리스 해시를 연결점으로 보존한다.

기존 조건 선택은 원장의 `logical_requests.parquet`에서 `mode=free8`, `info=IC-b`, `budget=B1`, `replicate∈{1,2}`, `condition∈{C4R,C6-E}`로 고정한다. 이 필터는 조건별 2,300행이며 각 조건에서 두 모델·두 회차·575개 기업이 완전하게 균형을 이뤄야 한다. 각 행은 `generation_ledger.sqlite`의 `payloads` 및 선택된 `attempts`에 연결되어야 하며 선택 원문 해시와 payload 해시를 기록한다.

원장 parquet의 선택 행에서 `request_state=WAITING_PARENT`가 남아 있더라도, 재사용 자격은 그 열 하나로 판정하지 않는다. 현재 확인된 선택 원장은 조건별 2,300개 모두 `DELIVERED_LOCKED`, 선택 시도·원문·응답 해시·시스템/사용자 프롬프트가 있다. 최종 매니페스트는 parquet 요약 상태와 실제 원장 상태를 모두 보존하고, 이 불일치를 기록한다. 선택된 응답을 점수와 대조하거나 기존 결과를 맞추는 행위는 금지한다.

## 4. 프롬프트·모델·조건 차이와 해석 경계

- 기존 N/R은 생성된 원문 그대로 C4R/C6-E에서 가져온다. 기존 두 조건은 TASK 문구가 서로 다르며, C6-E에는 RL 참조 블록이 있다.
- 신규 T/RT는 v5.1 파일럿에서 고정한 공통 TASK 문구를 사용한다. T는 N 본문에 고정된 캡션과 10행 Simulator 표를 추가하고, RT는 R의 참조 블록 및 동일한 표를 제공한다. 결과표를 설명하거나 행동 선택을 지시하는 추가 문구를 넣지 않는다.
- 신규 T/RT의 기준 기업 정보·C4 초안은 해당 기업·모델·회차의 정확한 동결 C4 응답 및 본문에서 가져온다. 47개 STRICT ITT 무효 초안은 원문을 보존하며 표의 초안 행동 행만 A0다. 첫 회차 파일럿 요청은 저장된 파일럿 요청과 프롬프트 해시까지 일치해야 한다.
- N/R/T/RT의 정확한 모델 ID, HIGH 추론 설정, 행동 계약, 출력 스키마, 도구 미사용 조건을 고정한다. T/RT 표는 조건 간 행·숫자·행동벡터가 바이트 수준으로 동일해야 한다. Q는 같은 모델과 1회 실행이며, 원 기업정보와 9개 고정 행동별 5개 재무항목 예측만 요청한다.
- 기존 N/R과 신규 T/RT의 생성 시점이 다르고, 새 T/RT의 공통화된 TASK 문구도 과거 N/R과 다르다. 따라서 전체 575개 표본의 `T−N`, `RT−R`, 상호작용은 결과표 정보만의 순수 인과효과가 아니라 **결과표를 포함한 공통화 프롬프트 패키지와 기존 조건의 비교**로 해석한다. 동일 시기·동일 공통 TASK의 파일럿 100기업 N/R/T/RT 2×2 분석을 별도 보조 결과로 함께 제시한다. 두 추정치를 섞거나 파일럿을 독립된 표본외 검증으로 부르지 않는다.
- `RT−R`은 기존 RL 참조 응답과 결과표를 포함한 새 생성 간의 비교다. 이를 무작위 동시기 대비로 과장하지 않고, 100기업 동시기 보조 대비와 생성 시점·프롬프트 차이를 나란히 보고한다.

## 5. 고정 재무·예측 채점 기준

정책 성능은 전체 생성 완료 후 기존 α·β·γ만 적용한다. 평가모형 δ·ε, 행동모방 정책 E2-B, Oracle 결과·가중치·행동순위는 LLM 요청에 전달하지 않는다. v5.1의 T1–T9, H1 주 지표(α `RT−R`), 모델별·통합 효과와 paired 95% 신뢰구간, β·γ, P0/P2/P3, 구성·배정 분해, 행동축, Q 및 S0/S1/S2 분석을 유지한다.

Q의 방향/금액 불일치는 응답 원문 그대로 보존하고 보정하지 않는다. 사전 고정 채점은 다음과 같다.

1. 방향 정확도에는 모델이 제출한 `direction` 범주를 그대로 사용하고, 실제 변화 범주는 v5.1의 양의 기초 총자산 대비 1bp 기준으로 판정한다.
2. 금액 오차에는 모델이 제출한 유한 signed `change_thousand_krw`를 그대로 사용한다. 방향 텍스트와 부호가 충돌해도 부호를 뒤집거나 금액을 0으로 바꾸지 않는다.
3. 방향과 금액 부호 불일치는 별도 출력 무결성 지표로 보고한다. `no_material_change`에 0이 아닌 금액이 있으면 방향 범주는 그대로 채점하고 숫자는 그대로 오차 계산에 넣는다.
4. 잘못된 JSON, 누락/중복 후보, 비유한 숫자 또는 계약 위반 항목은 임의 대체하지 않고 구조·채점 불가로 분리한다. 분모·유효 응답 수를 조건·모델별 공개한다.
5. 실제 재무변화는 고정 행동을 S0/S1/S2 Simulator로 산출한다. S1은 확인된 장기전환 가산금리 +1%p 경로, S2는 COGS/SGA 절감 실현율 50% 경로를 사용한다. 두 경우 모두 생성 행동을 재생성/수정하지 않고 기존 α·β·γ로 재채점한다. S0 기준 주 가설은 유지한다.

## 6. 사전 비용 추정

파일럿 1,000개 응답의 실제 입력/출력 토큰을 T·RT·Q와 공급자별로 나누고, 파일럿 기록의 Batch 단가(OpenAI 입력/출력 USD 0.375/2.25 per million tokens, Google USD 0.125/0.75)를 5,150 신규 요청의 공급자별 수량(T 1,050, RT 1,050, Q 475)에 적용했다. 이 사용량 평균 기반 점추정은 **USD 69.84**다. 파일럿 요청별 비용 분산을 독립 반복으로 환산한 근사 단측 95% 상단은 **USD 70.49**다. 출력이 매번 32,768 토큰 상한까지 사용된다고 가정하고 파일럿 평균 입력량을 적용한 시나리오는 USD 260.89이며, 이는 실제 비용 상한이 아니다. 세 추정치는 청구액 견적 또는 비용 상한이 아니며 재시도 비용·요금 변경·토큰 분포 변화는 포함하지 않는다. 신규 생성 완료 후 실제 사용량으로 다시 기록한다.

## 7. 결과 공개 규칙

성능 결과는 v5.1의 조건·모델·회차를 보존해 표로 산출한다. 신규 조건과 재사용 조건의 원천, request ID, 부모 C4 ID/해시, prompt/body hash, 응답 해시, provider job, 사용량과 비용을 row-level execution manifest로 제공한다. 점수·통계·정책가치가 최초 생성되는 시점은 전체 신규 원응답 도착과 무결성 점검이 끝난 이후로 로그에 기록한다. 사용자 승인된 산출물은 `E2_FINAL_REPORT.md`, 결과표·그래프·실행/비용 로그, 재현 코드 및 원응답이다.

## 8. 과거 R6 복원 범위

최신 사용자 지시에 따라 R6만 과거 분석 경로 복원 대상으로 다시 포함한다. e18/e20의 기존 후보집합, 생성 조건, 선택 규칙, seed, 평가 호출 및 계산 순서를 원 코드·README·기존 결과로 확인하고 그대로 재실행한다. 필요한 기존 평가 자산은 과거 R6 복원에 한해 사용한다. 기존 기대표에 맞추기 위한 코드·데이터·통계 변경은 금지하며, 재구성이 불가능한 단계는 그 지점과 부족한 의존성만 보고한다. R6 결과는 E2 신규 성능 분석과 별도 표/부록으로 유지하고, 파일럿 또는 본실험 API 배치를 지연시키지 않는다. 다른 R1–R9 재현은 다시 열지 않는다.
