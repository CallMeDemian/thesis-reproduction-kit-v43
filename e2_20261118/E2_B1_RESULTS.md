# E2 B1 계산 진단 결과

작성일: 2026-11-18  
범위: 575개 기업의 P0–P5 탐색적 Simulator 진단, 고정 행동강도 비용배분 반사실, E2 10행 표 생성·QA, C2 계보 확인. 신규 LLM 호출과 RL 학습은 수행하지 않았다.

## 요약

1. **RL 행동 구성에는 관찰 가능한 개선 여지가 있다.** C3-E가 Heuristic OE를 고른 기업에만 고정 매출원가율 1단위 감소(P2)를 적용한 P3은 RL 대비 총가치가 일곱 평가기 모두에서 높았다. α 증분 +0.078 [0.049, 0.111] 중 구성가치가 +0.065 [0.045, 0.087]이었고, 배정가치 증분 +0.012의 신뢰구간은 0을 포함했다. 이는 이 고정 후보와 표본에서의 탐색 결과다.
2. **Simulator 표는 합리적인 정보 입력 후보지만, Oracle 정보와 완전히 독립적이지 않다.** 재무변화 표는 10개 행동의 시뮬레이션 결과를 오류 없이 만들 수 있었다. 또한 같은 총 행동강도와 같은 다른 6개 축 아래에서 COGS/SG&A 배분만 바꾸자 일곱 점수와 재무제표 결과가 달라졌다. 다만 이 값은 Simulator의 결과이고, 재무표가 평가변수 또는 비율을 간접 전달할 수 있다.
3. **E2의 제한된 LLM 파일럿은 실행 가치를 갖는다.** 비용배분·정책 구성 개선 여지가 확인되어, LLM이 해당 정보를 실제 행동 수정에 활용하는지 시험할 근거가 생겼다. 우선 E2-N/R/T/RT를 제한 표본에서 검토하고 E2-Q는 판정 임계값을 사전에 고정한 뒤 포함한다. C2 매핑을 확인할 때까지 E2-B만 제외하는 편을 권한다. 이는 파일럿 승인 요청이 아니라 기술적 가치 판단이며 이번 작업에서는 호출하지 않았다.

## 1. 정책 P0–P5: 총가치·구성가치·배정가치

같은 575개 기업, 동결 Simulator, 7개 평가기(α, β, γ, δ1, δ2, ε1, ε2)를 사용했다. 각 값은 같은 기업의 무행동 A0 Simulator 경로 대비 점수 변화다. 총가치 (V)는 기업에 실제 배정된 정책 행동의 평균 점수 변화, 구성가치 (C)는 다른 기업에 배정한 행동을 교차기업으로 재배정했을 때의 평균 변화, 배정가치 (A=V-C)다. 구성과 배정은 성과를 분해하는 기준이며, 정책별로 기능을 전담한다는 뜻이 아니다.

아래는 주 평가기 α·β·γ다. 7개 평가기의 정책별 전체값과 95% paired 기업 bootstrap 대비는 각각 `B1_diagnostics/b1_policy_value_decomposition.csv`와 `B1_diagnostics/b1_policy_contrasts_vs_rl_heuristic.csv`에 있다.

| 정책 | α V / C / A | β V / C / A | γ V / C / A |
|---|---:|---:|---:|
| P0 RL C3-E | 0.923 / 0.583 / 0.340 | 0.207 / 0.139 / 0.068 | 0.246 / 0.148 / 0.099 |
| P1 Heuristic OE | 0.765 / 0.765 / 0.000 | 0.278 / 0.278 / 0.000 | 0.194 / 0.194 / 0.000 |
| P2 고정 COGS −1 | 0.927 / 0.927 / 0.000 | 0.357 / 0.357 / 0.000 | 0.231 / 0.231 / 0.000 |
| P3 C3-E, OE 기업만 P2 | 1.001 / 0.648 / 0.352 | 0.247 / 0.171 / 0.076 | 0.258 / 0.162 / 0.096 |
| P4 0.5×C3-E + COGS −0.5 | 0.945 / 0.794 / 0.151 | 0.295 / 0.269 / 0.025 | 0.235 / 0.198 / 0.037 |
| P5 재무결과 기준 선택 | 0.852 / 0.540 / 0.312 | 0.306 / 0.180 / 0.126 | 0.248 / 0.137 / 0.111 |

P3−P0의 전체 7평가기가 양수였지만, 구성·배정 분해에서는 구성가치 증가가 주된 차이였다. 주요 3평가기의 차이는 다음과 같다.

| 평가기 | 총가치 V | 구성가치 C | 배정가치 A |
|---|---:|---:|---:|
| α | +0.078 [0.049, 0.111] | +0.065 [0.045, 0.087] | +0.012 [−0.013, 0.038] |
| β | +0.041 [0.024, 0.064] | +0.032 [0.022, 0.044] | +0.008 [−0.005, 0.024] |
| γ | +0.012 [0.004, 0.019] | +0.015 [0.009, 0.020] | −0.003 [−0.010, 0.004] |

P2는 α 구성가치를 RL보다 +0.344 [0.274, 0.416] 높였지만, 배정가치는 −0.340 [−0.419, −0.265] 낮았다. 총 α 차이는 +0.004 [−0.098, 0.107]로 불확실하다. 고정 비용행동의 구성은 점수가 높아도 기업별 연결을 잃을 수 있음을 보여 준다. P5는 Simulator의 세전이익·현금 변화만으로 행동을 선택했으며, RL 대비 α는 −0.071 [−0.191, 0.049], β는 +0.099 [0.049, 0.152], γ는 +0.001 [−0.052, 0.056]이었다. 재무 Simulator 선택 기준이 일곱 평가기에 고르게 작동하지 않았다.

별도 **동일 표본 내 Oracle 상한 진단**으로, 606개 행동 격자에서 각 기업의 α 최대점 행동을 골랐다. 해당 정책의 α 총가치/구성/배정은 1.735/0.403/1.332였다. 이 선택에는 같은 α 평가점수를 직접 사용했으므로 in-sample 진단이며, 실제 배포 정책·LLM 참조·결과표 입력으로 사용하지 않는다. 전체 평가기별 Oracle 선택 결과는 `B1_diagnostics/b1_oracle_grid_upper_bound_separate.csv`에 분리했다.

## 2. 비용배분 Simulator 반사실

`e33_costmix.py`와 `e34_costmix_noref.py`는 기존 LLM 행동 사이에서 관측된 COGS 비중과 점수의 기업 내 연관을 분석한다. 그 기울기는 배분만 바꾼 효과가 아니다. 별도 반사실에서는 e33의 사전 규칙에 해당하는 strict usable 비용중심 행동 2,728건·333개 기업을 사용했다. 원래 행동의 COGS/SG&A 절대 정규화 강도 합, 나머지 6축의 부호와 크기는 고정하고 비용축의 부호를 감소 방향으로 두어 COGS 비중 0%, 25%, 50%, 75%, 100%를 각각 Simulator에 입력했다. 원래 배분도 비교 기준으로 다시 계산했다.

총 행동강도 보존의 최대 오차는 2.22×10⁻¹⁶, 다른 축의 변경은 0, 행동계약 위반과 Simulator 실패는 0건이다. 16,368개 결과는 실제 결과가 아닌 동일 Simulator 안의 통제된 반사실 계산이다.

COGS 비중 100%와 0% 배분의 paired 기업 차이는 다음과 같다. 신뢰구간은 333개 기업 bootstrap이다.

Simulator가 배분 변화에 민감함을 확인했을 뿐, 실제 기업에서 COGS 배분을 바꾸면 같은 성과가 난다는 인과효과로 해석하지 않는다. 5개 비율과 각 관측 원배분을 포함한 상세 결과는 `B1_diagnostics/cost_allocation_counterfactual.parquet`, 대응별 평균·95% CI는 `B1_diagnostics/cost_allocation_counterfactual_paired_summary.csv`에 있다.

## 3. E2 10행 Simulator 표와 회계 QA

각 기업·모델·반복별 10행씩, 총 2,300개 표/23,000행을 만들었다. 표는 A0, 저장된 HIGH/free8/B1/C4 초안 행동 proxy, 행동계약의 8개 단일축 행동으로 구성되며, 행별 변화는 같은 기업의 A0 Simulator 경로 대비 다음 회계연도 변화다. 금액 단위는 천원(KRW thousand)이다. “이자비용” 열은 Simulator 상태의 `pure_interest_expense`로 계산했다. 결과표에는 평가점수·등급·평가기 가중치·행동순위를 넣지 않았다. E2-T와 E2-RT는 동일한 표 payload를 함께 참조하도록 저장했다.

단일축 행동의 계산 방향은 capex 축 +1, 총차입금 축 +1, 차환 축 +1, 재고·매출채권 회전율 +1, 매입채무 회전율 −1, COGS·SG&A 비율 −1 정규화 단위다. 매입채무 회전율의 방향은 동결 행동계약의 공급자금융 후보(WC2) 방향을 따랐다. 실제 E2 요청 전에는 프롬프트에 표시되는 행동 설명·방향을 이 표 스키마와 함께 고정해야 한다.

검증 결과:

- 575개 기업×2모델×2반복, 표마다 정확히 10행이며 11개 재무 열 결측은 0건이다.
- Simulator 실패 0건, 행동 범위·T≤1·동시제약 위반 0건이다.
- A0 행은 모든 금액 변화가 0이며, 자산=부채+자본 항등식 1천원 허용오차 실패 0건, 변화량 항등식 잔차 1천원 초과 0건이다.
- 비-A0 행 중 17,711행은 재무변화가 있었고 2,989행은 Simulator가 계산한 재무변화가 0이었다. 0효과는 실행실패와 별도로 기록했다.
- 47개 저장 C4 초안은 strict usable이 아니어서 A0 fallback으로 명시했다. 따라서 이 파일은 완성된 E2 요청 payload가 아니라 표 계산·스키마 QA 산출물이다. 실제 pilot에서 E2별 초안 행동이 정해지면 초안 행을 그 행동으로 계산하고 E2-T/E2-RT에 같은 payload를 제공해야 한다.

전체 감사용 결과는 `B1_diagnostics/e2_simulator_10row_tables.parquet`이고, 모델·반복별 실제 표 payload만 담은 prompt-view는 `B1_diagnostics/e2_simulator_10row_prompt_view.parquet` 및 `B1_diagnostics/e2_simulator_10row_prompt_example.csv`다. 원본 예시와 행별 QA 요약은 `B1_diagnostics/e2_simulator_10row_example.csv`, `B1_diagnostics/e2_simulator_10row_action_summary.csv`에 있다. E2-T와 E2-RT에는 동일한 prompt-view 표를 제공해야 한다. Simulator 결과표의 금액변화는 재무상태 입력의 분자·분모를 다시 계산하는 데 쓰일 수 있어 간접 평가정보 전달 가능성이 남는다.

## 4. C2와 E2-B

현재 GitHub source의 `v43_training.py`에서 Stage4는 관측/투영된 후보행동의 soft target으로 actor를 학습하는 행동모방(BC) 단계다. `v43_checkpoints.py`의 계약은 Stage4 checkpoint를 `producer_stage=Stage4`, `trained`, 9개 `action_ids`, action-contract hash, Stage3 상위 checkpoint hash로 식별한다.

다만 재현 키트의 `C3E_firm_actions.parquet`에 있는 `C2_action`(OE 398개, DL 177개)을 Stage4 checkpoint의 기업별 actor 출력으로 잇는 decision crosswalk를 찾지 못했다. C3E 정의에는 Stage4 checkpoint 해시가 기록돼 있으나, 해당 checkpoint 파일과 실행 manifest, C2 행동을 생성한 575개 기업별 결정표의 매핑이 이 릴리스에 없다. 따라서 **Stage4가 BC라는 점은 코드로 확인했으나, 이 `C2_action`이 동일한 Stage4 정책 출력인지 확인하지 못했다. E2-B만 보류한다.** 확인에는 해시가 연결된 Stage4 checkpoint와 실행 기록, Stage4/C2 기업별 결정표 및 후보 ID crosswalk가 필요하다.

## 5. v4·E2_PROTOCOL 보완과 결정

- `E2_PROTOCOL.md` 및 v4의 B1 “자료/계산 미확보” 기록을 실제 산출물 기준으로 갱신했다. H1–H6, 사전 통계 기준, R1–R9 수치는 변경하지 않았다.
- v4 R2의 C6-E−C4R 증분을 7개 평가기별·모델별 효과와 95% CI로 펼쳐 썼다. R6의 불일치는 그대로 두었고 기대값 맞추기는 하지 않았다.
- 수정 전 v4와 프로토콜은 `source_inputs/GATE1_ORIGINALS/`에 보존했다. SHA-256은 각각 `47AE0B6F4D092B5A6E19595F58B05548816B92B8EEAF63EE869FD11D32171712`, `9BB47872D1F4D00771BEAA1B78367ACCF4AFC9A64DC06492EC9B8B7395173953`이다.
- 모든 B1 결과는 탐색 진단이며, 같은 575개 기업과 기존 결과를 기반으로 한다. Oracle로 선택한 606격자 진단은 별도 파일에 분리했고, 실제 정책이나 LLM 참조로 취급하지 않는다.

### 세 질문에 대한 최종 답

1. **RL 구성의 개선 여지:** 있다. P3은 매출원가 고정행동으로 OE 일부를 대체해 7개 평가기에서 모두 더 높았고, α·β·γ에서 증가의 대부분이 구성 성분에 나타났다. 이는 제한된 후보와 기존 표본의 Simulator 점수면에서 확인한 여지이며, 정책 원인이나 실제 실행성과를 입증하지 않는다.
2. **Simulator 결과표의 기술적 타당성:** 있다. 정확한 재무표 생성과 균형 검사가 가능했고, 행동배분을 고정 강도 아래 변경하면 평가점수와 실제 Simulator 재무항목이 달라졌다. 다만 LLM이 표에서 평가모형 입력을 추론할 수 있으므로, “평가정보를 전혀 주지 않는다”는 설명은 피해야 한다.
3. **LLM 파일럿 가치:** 제한 파일럿은 가치가 있다. C2 계보 확인 전에는 E2-B만 제외하고 N/R/T/RT를 검토할 수 있으며, Q는 변화율·zero-effect 기준을 사전에 고정한 뒤 포함한다. 이 진단만으로 LLM 개선이 입증된 것은 아니며, 12,650건 본실험을 정당화하지도 않는다. 11월 30일 미팅과 12월 2일 초안 일정상, 교수 미팅 후 제한 파일럿 여부를 결정하고 본실험은 초안 기여를 뒷받침하는 데 꼭 필요한 경우에만 별도로 검토하는 것이 적절하다.

**중단 상태:** B1 계산과 문서 정정을 완료했다. 새 LLM API 호출, 파일럿, 본실험, RL 재학습은 하지 않았다.
