## 0. 연구 목적과 주장

> 평가용 신용점수를 직접 제공하지 않고, 학습된 RL 정책과 재무 Simulator의 정보를 활용해 LLM의 기업별 권고 품질을 개선할 수 있는지 검증한다.

여기서 권고 품질은 본 연구의 동결된 재무 Simulator와 Oracle 평가모형이 산출하는 정책가치를 뜻한다. E2의 결과표도 Simulator가 생성한 결과다. 실제 기업이 권고를 집행한 뒤 관측한 재무결과가 아니다.

| 구분 | 기존에 확보한 근거 | 해석 경계 |
|---|---|---|
| 학습된 RL 정책 | 제한적 관측 신용등급 변동의 감독정보와 Simulator 기반 재무 보상을 이용해 기업별 8축 행동을 학습 | 실제 정책 집행 성과를 관측한 것은 아님 |
| 기존 RL 참조 효과 | 공식 E1 원응답·관측값·manifest를 재분석했고, 3,450행 α·β·γ 독립 재채점 게이트도 PASS했다. RL 행동이 OE와 달랐던 343개 기업에서 α 정책가치 차이는 GPT +0.156, Gemini +0.145; β는 −0.022, −0.018 | E1은 주 결과 후 추가 분석이며, C3-E 선택에도 α가 쓰였다. 실제 기업성과나 독립 표본외 검증이 아님 |
| 새 E2 가설 | Simulator 결과표를 RL 행동 참조와 함께 주면 RL 참조만 준 경우보다 기업별 권고의 α 정책가치가 높아지는가 | 아직 검증되지 않음. 같은 575개 기업과 기존 결과를 활용해 가설을 발전시켰으므로 독립 표본외 검증으로 부르지 않음 |

E1 재현에서 α 차이와 함께 β의 음의 차이가 확인됐다. 결과는 α·β·γ를 함께 제시하며 한 평가축의 개선을 전반적인 기업성과 개선으로 일반화하지 않는다. T5의 30개 수치 행은 분석 행 기준으로 공식 결과와 일치했고, 독립 재채점은 3,450개 요청 전부에서 α·β·γ 점수를 허용오차 내 재현했다.

## 1. 기존 분석과 신규 가설의 경계

기존 연구의 기술적 기여는 제한적 관측 신용등급 변동의 감독정보와 재무 Simulator 보상을 이용해 기업별 행동을 산출하는 RL 정책, 그리고 그 기업별 행동을 LLM의 참조로 제공하는 접근이다. 재현된 E1에서는 RL 참조와 고정 OE 참조의 차이가 α에서 양수였고 β에서 음수였다. R8은 RL과 LLM 모두 기업별 행동 배정에서 양의 성분을 보이되, 이 점수 표면의 RL 분해에서는 구성보다 배정 성분이 상대적으로 컸음을 보여 준다. 이는 관찰된 정책가치 분해이지 원인 입증은 아니다.

새 E2가 추가할 기술적 기여는 별도다. 이는 Simulator가 계산한 기업별 재무 금액 변화를 LLM 입력에 제공하는 것이 RL 참조보다 추가 정보를 주는지, 혹은 둘을 함께 제공할 때 유용한지 측정한다. E2-T/E2-RT에서 이 결과표는 점수의 정답표가 아니라 Simulator 출력이다. 그럼에도 원 재무정보와 결합되면 Oracle 입력 비율을 유추할 가능성이 있으므로 완전한 평가정보 차단이라고 부르지 않는다.

검증기 기반 행동선택은 여러 권고 후보를 평가모형의 점수·순위로 비교해 고른다. RL 참조는 평가점수와 후보 순위를 프롬프트에 보여 주지 않고, 기존 학습 정책의 기업별 행동을 제공한다. 이 구분은 정보 제공 및 행동 선택 방식의 차이다. 평가모형 교체에 대한 강건성이 실제 기업성과 일반화를 뜻하지는 않는다.

## 2. 구성 가치와 배정 가치

기업 i에 정책이 준 행동을 aᵢ, 기업 i가 행동 a를 받았을 때 무행동 대비 점수 변화를 S(i,a)라 한다.

정책가치 V = (1/N) Σᵢ S(i,aᵢ)

구성 가치 C = (1/(N(N−1))) Σᵢ≠ⱼ S(i,aⱼ)

배정 가치 A = V − C

- 구성 가치: 정책이 만든 행동의 종류·조합·강도 분포를 기업과 독립적으로 재배정했을 때의 평균 가치.
- 배정 가치: 원래 기업과 행동을 연결했을 때 구성 가치에 더해지는 가치.
- 이 분해는 성과를 요약하는 기준이며 원인을 입증하거나 RL과 LLM의 기능을 배정하는 방법론은 아니다.
- “RL은 배정을 잘하고 구성을 못 한다”는 표현은 계산된 분해에서 관찰될 수 있는 해석일 뿐, 확인된 원인이 아니다.
- 행동 후보가 9개뿐이라는 제약, 학습 보상, 정책 선택, 실제 행동 강도 중 무엇이 결과에 기여했는지는 이 분해만으로 판별할 수 없다.
- R8은 GitHub LFS 해시와 연결된 Simulator·Oracle 및 606행동×575기업 점수면으로 재현했다. 교차기업 재배정 결과는 실행가능한 점수면에 대한 기술 분해다. 이 표는 새 실행 결과가 아니라 Gate 1의 재현 결과다.
- 모든 기업에 동일 행동을 주는 정책의 배정 가치는 0이어야 한다.

재현된 α 분해에서 RL의 구성 성분(0.584)은 GPT/Gemini C6-E(0.615/0.621)보다 낮고, 배정 성분(0.339)은 높았다(GPT 0.297, Gemini 0.264). 전체 정책가치는 RL 0.923, GPT C6-E 0.912, Gemini C6-E 0.885였다. LLM도 양의 배정 성분을 보였으므로 “RL은 배정을 하고 LLM은 구성을 한다”는 기능 분담은 성립하지 않는다. 9개 고정행동 후보, 학습 보상, 정책 선택, 행동 강도 중 무엇이 차이를 만들었는지는 이 분해만으로 식별할 수 없다.

## 3. E2 조건

모든 수정 조건은 같은 기업·모델·반복에서 같은 초안으로부터 별도 생성한다. 한 조건의 출력을 다음 조건에 전달하지 않는다. 1차와 2차 반복은 각기 대응되는 기존 초안에서 시작한다.

| 조건 | 참조 | Simulator 결과표 | 역할 |
|---|---|---|---|
| E2-N | 없음 | 없음 | 자기 재검토 기준 |
| E2-R | E1의 C3-E 기업별 행동 | 없음 | 기존 RL 참조 재현 |
| E2-T | 없음 | 공통 10행 | Simulator 결과표의 추가 효과 |
| E2-RT | E2-R과 동일한 참조 | E2-T와 바이트 단위로 동일한 10행 | 제안 조합 |
| E2-B | 검증된 행동모방 정책의 기업별 행동 | 없음 | 정책 학습단계 비교. C2 교차표가 확인되기 전 실행 불가 |
| E2-Q | 수정 조건 없음 | 없음 | 기업별 행동의 재무결과 예측 정확도 보조 측정 |

E1 release에는 provider request shard 8개와 request manifest가 있다. 실제 request body 안에 C4 초안과 조건별 행동 reference가 들어 있고, manifest의 payload/body hash로 연결된다. E2-R은 이 E1 reference 표현을 동일하게 보존해야 한다. E2-T/RT/Q에 쓰일 최종 request body와 payload hash는 아직 생성·동결되지 않았다.

계획된 수정 생성 요청은 5조건 × 575개 기업 × 모델 2종 × 반복 2회 = 11,500건이다. E2-Q는 575 × 2 = 1,150건으로 총 12,650건이다. 100개 기업 시범 1,200건은 별도다. 새 유료 API 호출·시범·본실험은 Gate 1 뒤 별도 승인 전에는 시작하지 않는다.

E1의 실제 요청 본문·모델 표기·조건별 payload와 C4 초안은 release shard 및 manifest에 보존돼 있다. E2 실행 전에는 이 입력을 기준으로 E2별 추가 문구를 확정하고, provider/model ID·버전·전체 prompt bytes·생성 설정·재시도와 실패 처리를 포함한 request manifest를 별도 동결해야 한다. E1의 입력이 있다는 사실만으로 E2 요청이 이미 고정된 것은 아니다.

## 4. 결과표 명세 및 정보 전달 감사

### 4.1 행과 열

E2-T와 E2-RT에 같은 기업별 10행을 같은 순서와 서식으로 제공한다.

1. 무행동(A0)
2. 해당 반복에서의 LLM 초안 행동
3–10. 행동 계약의 8개 축별 단일 1단위 행동

단일 1단위는 v43_action_contract.json의 축별 normalization_scale_by_dimension을 적용한다. 축 이름, 부호, 범위는 행동 계약에서 가져오며 임의로 재정의하지 않는다. 복수 행의 금액변화는 각 행동을 무행동 상태에서 따로 시뮬레이션한 결과다. 각 행의 변화량을 더해 혼합 행동의 결과로 제시하지 않는다.

예정 열은 매출액, 영업이익, 세전이익, 이자비용, 총차입금, 단기차입금, 현금및현금성자산, 유동자산, 유동부채, 자본총계, 영업활동현금흐름의 변화량이다. B1 산출에서 금액 단위는 천원(KRW thousand), 시간축은 결정연도 다음 해, 변화량은 동일 기업 A0 경로 대비로 확인했다. 2,300개 표 모두 10행이고 실행 실패·행동위반·재무열 결측·회계항등식 검사 실패는 없었다. 47개 저장 C4 초안은 strict usable이 아니어서 A0 fallback으로 표시했다. 이는 고정 표 계산 QA를 뜻하며 최종 E2 요청 prompt가 동결되었다는 뜻은 아니다. B1 결과와 남은 구분은 `E2_B1_RESULTS.md`에 기록했다.

### 4.2 프롬프트와 공통 통제

- E2-T/E2-RT에 동일한 표, 열, 행, 순서, 숫자 자릿수를 사용한다.
- 참조 행동과 평가모형 점수·신용등급·평가모형 가중치·행동 순위를 결과표에 추가하지 않는다.
- 결과표 설명 문구는 데이터 단위·실행 조건 검증 후 고정한다. 초안에는 다음 의미를 전달한다: 표는 Simulator가 계산한 1년 뒤 재무제표 항목 변화이며 점수·등급·순위를 포함하지 않고, 여러 행동의 효과는 단순 가산되지 않을 수 있다.
- 특정 행동을 권하는 순위나 표현을 표에 붙이지 않는다.
- 결과표를 본 뒤 모델·평가모형 점수에 맞춰 프롬프트, 행동 후보, 표, 가설, 통계 기준을 바꾸지 않는다.
- 엄격 규칙 위반과 파싱 실패는 기존 프로토콜처럼 무행동 처리하고, 원응답과 처리 후 행동을 각각 보존한다.

### 4.3 Oracle seam 감사

금액 변화량 자체에 α·β·γ 점수나 가중치는 포함하지 않는다. 그러나 이 금액 항목들은 신용·재무 평가모형의 기초 입력 또는 해당 비율의 분자·분모가 될 수 있다. 기초 재무상태와 변화를 함께 제공하면 LLM이 평가모형과 가까운 비율을 계산할 수도 있다.

따라서 E2는 평가점수 직접 노출 금지 통제를 유지하되, “평가정보를 보지 않는다” 또는 “평가정보가 전혀 전달되지 않는다”고 주장하지 않는다. 변수별 입력·산식 연결을 확인하기 전에는 직접·간접 seam을 완전히 검증했다고 하지 않는다. 자세한 상태와 확인이 필요한 열은 ORACLE_SEAM_AUDIT.md에 기록한다.

## 5. E2-Q

초안의 재무정보와 본인 행동 및 8개 축 단일 행동에 대한 Simulator 결과 방향을 추정하게 한다. 질문 대상 예정 항목은 세전이익, 이자비용, 총차입금, 현금및현금성자산, 유동부채다. 방향 오류, 변화율 크기 오류, 효과가 거의 없는 항목의 거짓 변화 주장 비율을 보조로 계산한다.

분모가 0에 가깝거나 기초값이 음수일 수 있는 항목의 변화율 정의와 ‘변화 없음’ 임계값은 본 실행 전 확정해야 한다. 해당 규칙이 고정되지 않으면 E2-Q는 실행하지 않고, 이 결과를 결과표 조건의 근거로 사용하지 않는다.

## 6. 가설 및 분석

| 가설 | 대비 | 역할 |
|---|---|---|
| H1 | E2-RT − E2-R의 α 정책가치 | 유일한 주 가설 |
| H2 | 같은 대비의 구성 가치 및 배정 가치 | 보조 분석 |
| H3 | E2-RT 대비 C3-E 및 고정 매출원가율 1단위 행동 | 보조 분석 |
| H4 | E2-R − E2-B, E2-B − E2-N | 행동모방 교차표 검증 후 보조 분석 |
| H5 | E2-RT − E2-R − E2-T + E2-N | 두 정보원 간 상호작용, 보조 분석 |
| H6 | E2-Q 결과 예측 정확도 | 보조 분석 |

### 6.1 주 분석

- 주 지표는 사전 정의된 α 정책가치 차이다.
- 각 기업에 대해 E2-RT−E2-R 차이를 2모델×2반복으로 평균하고, 기업 단위 평균의 95% CI가 0보다 큰지 한 번 판단한다.
- 모델별 효과크기와 95% CI를 별도로 보고한다. 모델별 추론에는 두 모델 대비의 Holm 보정을 함께 보고한다.
- β·γ 결과를 모든 주요 대비와 함께 보고한다. α 개선이 β 또는 γ에서 악화와 함께 관찰되면 이를 숨기지 않는다.
- 결합 평균이 양수라도 각 모델 효과와 CI가 각각 지지하지 않으면 “두 모델 모두 개선”이라고 하지 않는다.
- 유의하지 않은 차이를 동등, 효과 없음 또는 손실 없음으로 기술하지 않는다. 동등성을 주장하려면 별도의 사전 한계와 검정이 필요하다.
- 신뢰구간은 기업을 재표집 단위로 하며 같은 기업의 모든 조건·모델·반복을 함께 이동한다. 10,000회 paired cluster bootstrap, percentile 95% CI, NumPy PCG64, seed 20261118을 사용한다. 동일 재표집 인덱스를 전체 지표에 적용한다.
- H2–H6은 보조로 유지하고 탐색적 결과로 표시한다. H3·H4의 복수 모델 대비에는 해당 family 안에서 Holm 보정을 보고한다.
- 결과를 보기 전에 분석 스크립트와 protocol hash를 동결한다. E2 실행 후 지표나 검정 기준을 바꾸지 않는다.

두 모델과 네 실행을 한 평균으로만 보고하지 않는다. 각 모델의 2회 평균 효과·불확실성과 실행별 분포를 병기한다. Wilcoxon 검정은 사전 정의된 보조 분석으로만 보고하며 주 판정을 대체하지 않는다.

## 7. B0·B1 준비 및 중단 조건

### B0 — 프로토콜 고정

E2_PROTOCOL.md에 본 설계의 조건·행렬·10행 구조·통계·Oracle seam·실패 처리·가설·금지된 수정 사항을 기록했다. 그 파일의 SHA-256은 Gate 1 보고에 남긴다. 이는 설계 버전의 고정 해시이지, 누락 입력까지 해결된 실행 승인이라는 뜻은 아니다.

아래 항목이 채워지고 검토되기 전까지 B0는 실행 준비 완료가 아니다.

- E1 release shard/manifest에서 추출·기록한 기준 request body와 reference payload hash, E2별 완성 prompt bytes 및 request manifest hash
- E2 대상 575개 기업의 firm_key 집합과 동결 baseline 금융정보 파일 해시 (기업 키 교차는 확인됐으나 E2 산출 manifest에 다시 고정)
- 검증된 기업별 Simulator·입력 contract를 연결한 E2 행 생성 스크립트와 출력 schema; 표시 부호·반올림·결측·실행불가 규칙
- 전체 재무제표 항등식과 각 행동의 실행 가능성·동시 행동 제약
- α·β·γ Oracle 식과 결과표 항목의 변수별 직접·간접 연결표
- C2 또는 행동모방 정책의 정확한 source id와 575개 기업의 출력 행동
- E2-Q의 변화율 분모·임계 규칙
- 실제 요청 모델 ID·버전·비용·rate limit·고정 생성 설정

### B1 — 고정 정책 계산 진단

P0–P5는 가설 변경 근거가 아닌 탐색 진단으로만 사용한다. 값이 C3-E보다 낮아도 H1–H6을 변경하지 않는다.

| 정책 | 정의 |
|---|---|
| P0 | 검증된 C3-E 기업별 행동 |
| P1 | Heuristic 고정 OE 행동 |
| P2 | 매출원가율만 계약상 1단위 감소한 고정 행동 |
| P3 | C3-E 행동. 단 C3-E가 OE를 고른 기업은 P2 행동으로 대체 |
| P4 | C3-E 행동 0.5배 + 매출원가율 0.5단위. C3-E가 OE인 기업은 P2. 행동예산·동시제약 별도 검사 |
| P5 | 후보(C3-E 행동, 8개 축 단일 1단위 행동, P4 행동) 중 (세전이익 변화 + 현금및현금성자산 변화) / 기초 총자산이 가장 큰 행동. 동률은 C3-E 행동 |

교란 조건(장기 전환분 가산금리 +1%p, 비용절감 실현율 50%)은 e15–e26의 실제 구현과 동일 입력이 확인되는 경우에만 탐색적으로 계산한다. 재현이 안 되면 구현을 새로 추측하지 않는다.

P0–P5 및 606행동 Oracle 상한, 10행 재무표, 비용배분 반사실을 575개 기업에 대해 생성하고 행동계약·금액단위·회계항등식 QA를 마쳤다. P5는 `(세전이익 변화 + 현금 변화)/기초 총자산`만으로 선택했다. Oracle 점수 최대화는 별도 in-sample 상한 진단이며 정책·prompt 참조가 아니다. 세부값·해시·한계는 `E2_B1_RESULTS.md`와 `B1_diagnostics/`에 있다. E2 LLM 요청용 최종 prompt·요청 manifest, 47개 fallback을 대체할 실제 E2 초안 행동, E2-Q 판정 임계값, C2 crosswalk는 아직 고정 또는 확인되지 않았다.

## 8. 제출 일정과 연구 범위 판단

E2는 Simulator 결과표가 RL 참조에 더하는 증분 정보를 평가해 연구 기여를 확장할 수 있지만, 기존 기술 기여를 성립시키는 선행조건은 아니다. E1 및 R1–R5·R8 재현과 이번 B1은 RL reference의 평가 프로필·구성/배정 분해·행동 구성 개선 여지를 보여 준다. E2는 같은 기업 표본을 활용하며 결과표가 Oracle 입력 특성을 간접 전달할 수 있다. 10행 계산 QA는 완료됐으나 최종 prompt·요청 manifest·E2 초안 행동은 미동결이다. Stage4가 코드상 BC라는 점은 확인했지만 C2_action과 Stage4 기업별 출력을 잇는 crosswalk가 없어 E2-B만 보류한다.

11월 30일 지도교수 미팅 전에 이 v4와 재현·근거 감사를 중심으로 기존 주장과 한계를 정리하고, 12월 2일 논문 초안에는 확인된 기존 결과만 반영하는 편이 합리적이다. E2는 독립된 추가 연구로 미루는 것을 권고한다. 필요성이 확인되면 미팅에서 설계와 자료 접근을 승인받고, 표본·API 비용·도입 일정이 초안 부담을 넘지 않는지 별도 결정한다.

## 9. 이 Gate 1에서 승인되지 않은 작업

새 유료 LLM API 호출, 100개 기업 파일럿, 12,650건 본실험, RL 재학습, Frozen 데이터·논문·발표 원본 수정, 원격 Git push 또는 PR 병합은 수행하지 않는다. 1차 관문은 보고 완료 후 종료한다.
